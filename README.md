# goTrust

goTrust 是一个 aTrust 桌面客户端：在托盘里登录 Sangfor aTrust 网关，保持会话，
并在本机回环地址上提供 SOCKS5 与 HTTP 代理，让浏览器或其他程序访问内网。

支持 Linux、macOS 与 Windows，界面为中文。它有意保持简单：

* **只支持 aTrust。** 不兼容 EasyConnect。
* **不建 TUN 设备，不改系统代理，不需要管理员权限。** 程序以当前用户身份运行；
  需要访问内网的程序把代理指向 goTrust 提供的本地端口即可。
* **一个配置对应一个网关，同时只保持一个会话。** 多个账号是同一份配置文件里的多个
  “配置”，同一时间只有一个处于连接状态。

## 安装

从 [GitHub Releases](https://github.com/YangtseSu/goTrust/releases) 下载对应平台的压缩包：

| 系统 | 文件 |
|---|---|
| Linux x86_64 / aarch64 | `gotrust_<版本>_linux_amd64.tar.gz`、`gotrust_<版本>_linux_arm64.tar.gz` |
| macOS（Intel 与 Apple Silicon 通用） | `gotrust_<版本>_darwin_universal.tar.gz` |
| Windows x86_64 | `gotrust_<版本>_windows_amd64.zip` |

解压后直接运行 `gotrust`（Windows 为 `gotrust.exe`）。Linux 还需要系统里有 GTK3、
libayatana-appindicator 和 hicolor-icon-theme；macOS 与 Windows 不需要额外运行库。

这些包没有做代码签名：macOS 会提示来源不明的开发者，Windows 会显示 SmartScreen
提示。需要自行构建的，见 [`docs/development.md`](docs/development.md)。

## 第一次使用

1. 启动 goTrust。默认只显示托盘图标，窗口可以从托盘打开。
2. 打开“设置 → 连接”，填写网关地址、端口和用户名，勾选“保存密码”并输入密码，
   然后保存。
3. 设置窗口里的“获取认证方式”会向网关询问认证方式。留空表示自动：网关只提供一种
   就直接使用，提供多种时登录过程中会弹出选择。
4. 回到主窗口按“连接”。首次登录通常需要点一次图形验证码；网关要求其他二次认证时，
   窗口会换成对应面板。
5. 连接成功后，主窗口列出该账号可访问的资源，代理地址显示在窗口里。

## 代理怎么用

默认监听：

| 协议 | 地址 |
|---|---|
| SOCKS5 | `127.0.0.1:1080` |
| HTTP | `127.0.0.1:1081` |

端口可以在“设置 → 代理”里修改，下次连接生效。主机名在隧道内解析，不需要改动系统
DNS，也不需要 fake-IP。

命令行示例：

```sh
curl --socks5-hostname 127.0.0.1:1080 http://内网地址/
curl -x http://127.0.0.1:1081 http://内网地址/
```

浏览器或其他程序里，把“SOCKS5 代理”设为 `127.0.0.1:1080`（勾选“代理 DNS”），
或把 HTTP 代理设为 `127.0.0.1:1081`。

两个监听只绑定回环地址；填 `0.0.0.0:1080` 这样对外暴露的地址会被拒绝。

## 登录时会遇到什么

* **图形验证码**：窗口显示图片，按顺序点击字符后提交。可以撤销、清空或取消；
  取消即放弃这次登录。
* **一次性验证码**（短信、TOTP、动态口令）：面板显示网关的提示和输入框。网关允许时
  可以跳过以后的二次认证。TOTP 还可以选择保存密钥，之后由 goTrust 自己生成验证码；
  密钥只在勾选“保存密码”的配置里保存。
* **外部登录**（CAS / OAuth2）：用系统浏览器打开网关的登录页，登录完成后把浏览器最终
  停留的回调地址粘贴回面板。地址格式不对会在面板里直接提示。
* **绑定设备**：网关要求把本机绑定到账号时，会弹出确认面板；允许后继续登录，取消则
  终止登录。
* **重置密码**：网关要求修改密码（例如 90 天到期，或管理员重置后的首次登录）时，
  登录流程会停下来显示重置面板，按网关给出的密码规则填写旧密码和新密码即可。

会话在线时，也可以在“设置 → 连接 → 密码安全 → 重置密码”里主动修改密码。修改成功后，
该账号在其他终端的会话需要重新登录。

## 设置项

| 分组 | 作用 |
|---|---|
| 配置 | 新建、复制、重命名、删除账号配置；切换配置会先断开当前会话 |
| 连接 | 网关、端口、用户名、认证方式、登录域、密码与是否保存 |
| 代理 | SOCKS5 与 HTTP 的监听地址，下次连接生效 |
| 保活 | 是否发送保活请求、间隔、手工目标，下次连接生效 |
| 启动 | 登录系统时启动、启动后自动连接、只显示托盘、断线后自动重连 |
| 终端管理 | 门户里该账号的设备列表：受信设备与临时登录记录，可刷新、信任或取消信任本机 |
| 高级 | 详细日志、日志目录、登录数据文件路径、设备标识 |

完整的配置字段说明见 [`docs/configuration.md`](docs/configuration.md)。

保活默认每 90 秒向内网发一个真实的 HTTP 请求；手工目标优先于自动推导的目标。
`https://` 目标不会续期会话，请使用 `http://` 地址。

断线后自动重连默认关闭。开启后按 1/2/4/8/16 秒重试，最多 5 次；需要验证码或二次
认证时停止重试并弹出面板。没有保存密码时不会自动重连，因为一次重连就是一次完整登录。

## 托盘

托盘菜单显示当前状态（`已连接 203.0.113.4`、`连接中`、`失败: …`）、连接/断开开关、
配置子菜单、显示窗口、打开默认应用、设置和退出。工具提示同时显示最后一次保活结果。
点击托盘图标（GNOME 里是双击）打开主窗口。

“登录系统时启动”会写入系统的自启动项；若同时开启“只显示托盘”，开机后只有托盘图标。
“启动后自动连接”需要已保存的密码，否则会显示窗口并说明原因，而不是静默失败。

## 资源列表

登录后主窗口列出账号可访问的资源：门户应用（带分组和打开方式）、域名规则、IP 地址与
网段、DNS 名称映射。单个主机允许 443 或 80 时会给出 `https://` 或 `http://` 链接，
可以一键打开或复制。只打开 `http`/`https` 链接，门户给出的其他协议不会被本机程序打开。

最近一次的列表会缓存到配置文件旁的 `resources.json`（0600），其中只有内网地址，
没有凭据。命令行可以用 `gotrust-cli --print-resources` 直接打印这份缓存。

## 日志

日志写在 `$XDG_STATE_HOME/gotrust/gotrust.log`（Linux）、`~/Library/Logs/gotrust`
（macOS）或 `%LocalAppData%\gotrust\logs`（Windows）。文件权限 0600，单文件 5 MiB，
保留三个历史文件。密码、cookie、会话令牌和验证码内容在落盘前会被打码。
“设置 → 高级 → 打开”可以直接打开日志目录。

## 命令行

`gotrust-cli` 是没有界面的版本，适合服务器或远程主机：读取同一份设置、登录、提供同样的
代理端口。登录过程中需要人工操作时，它会在 `127.0.0.1` 上开一个一次性网页，打印地址
（`--print-url` 则只打印、不打开浏览器），在网页里完成验证码、一次性验证码或回调地址。

```sh
gotrust-cli [--config 文件]                  # 登录并保持运行，直到 Ctrl-C 或 SIGTERM
gotrust-cli [--config 文件] --status         # 该配置是否正被某个进程使用
gotrust-cli [--config 文件] --print-resources
gotrust-cli --json                           # 资源与状态以 JSON 输出
gotrust-cli --version
```

| 退出码 | 含义 |
|---:|---|
| 0 | 正常运行结束；配合 `--status` 表示有进程正在使用该配置 |
| 1 | 设置、登录、监听或会话失败 |
| 2 | 命令行参数不正确 |
| 3 | `--status` 没有找到正在使用该配置的进程 |

同一个配置同一时间只能有一个进程使用：托盘版和命令行版分别使用不同配置时可以同时
运行，同一个配置则会被拒绝，避免共用同一份登录数据。

## 系统要求与已知限制

* Linux 需要 GTK3、libayatana-appindicator 与 hicolor-icon-theme；macOS 与 Windows
  使用系统自带的界面组件。
* macOS 与 Windows 的构建通过交叉编译检查，但还没有人在真机上运行过；遇到问题请提
  issue。
* 短信、TOTP、RADIUS 与 CAS/OAuth2 这些二次认证路径只有单元测试覆盖，尚未在真实网关
  上验证。主认证方式需要是密码、CAS 或 OAuth2；只支持短信主认证的网关无法使用，
  因为 goTrust 不收集手机号。
* 不提供 TUN 模式，也不修改系统代理；需要全局代理时请自行把程序或系统代理指向本地
  监听。
* 一个会话只属于它自己的连接：断开后再次连接就是重新登录，保存的登录数据不能用来恢复
  会话，所以自动连接需要保存密码。

## 安全说明

aTrust 客户端不校验网关证书：aTrust 部署通常使用客户端不携带的私有 CA，登录通道是
加密的，但链路上的伪造网关不会被发现。隧道本身有自己的密钥。两个代理监听按设计不做
身份验证，因此只能绑定回环地址。配置文件与登录数据文件权限均为 0600。
